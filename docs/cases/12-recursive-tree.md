# Кейс 12. Деревья: рекурсивный CTE

**Эндпоинт:** `GET /api/categories/{id}/products-count`
**Код:** `CategoryService.countProductsInTree`
**Тест:** `Case12RecursiveTreeTest`

## Ситуация

Нужно посчитать товары в категории **вместе со всеми подкатегориями** на любую глубину.
Сейчас рекурсия в Java: для каждой категории — запрос на детей (lazy-коллекция) и запрос на количество товаров.
У дерева 3 уровня — 35 запросов. У настоящего каталога 6–7 уровней и тысячи категорий.

```bash
curl "http://localhost:8080/api/categories/1/products-count"
```

## Задание

1. Посчитайте результат одним SQL-запросом с `with recursive`.
2. Где разместить запрос: native `@Query` в репозитории? Поддерживает ли рекурсивные CTE HQL в Hibernate 6+/7?
   Попробуйте оба варианта.
3. Для несуществующей категории эндпоинт должен по-прежнему отвечать 404.
4. Бонус: рассмотрите альтернативные модели хранения деревьев — materialized path (`ltree`), nested sets,
   closure table. Какие операции у каждой дешёвые, а какие дорогие?

**Готово, когда:** `Case12RecursiveTreeTest` зелёный (≤ 2 запросов, корректный результат для всех уровней).

## Подсказки

<details><summary>Подсказка 1</summary>

```
    <нерекурсивная часть: сама категория>

    <рекурсивная часть: дети тех, кто уже в tree>
)
select ... from tree ...
```
